\subsection*{Postcondition}
\begin{theorem}[Postcondition]
    For a given filter predicate and identifier expression,
    returns an error if the predicate contains a mis-specified truncation,
    none if the predicate is not a truncation,
    otherwise candidate per-identifier contribution bounds together with their deferred validation obligations.
\end{theorem}

\begin{proof}
    Both \texttt{AllHorizontal} and binary conjunctions retain only rows
    satisfying every child predicate. Line \ref{line:check_all} requires every
    child to be a truncation; all of their candidate bounds are then retained.

    In the comparison case, the algorithm first matches through the comparison operator
    to identify what should be the ``over'' and ``threshold'' expressions.
    Since window expressions are not valid row-by-row functions,
    they are unambiguously truncation expressions.
    Therefore, if the ``over'' expression is a window with the
    \texttt{GroupsToRows} mapping, as checked on line \ref{line:check_over},
    then any further failures to match the truncation predicates can now be raised as errors.
    This check covers \texttt{Expr::Over} and \texttt{Expr::Window}
    in the two supported Polars AST variants.
    The matcher additionally excludes window expressions with an \texttt{order\_by}
    expression on line \ref{line:check_order_by}. Such an expression is evaluated by
    Polars but is not part of the certified truncation ranking or partitioning keys;
    an unchecked order-by expression could fail depending on private values.

    The threshold must be an integer scalar representable as a \texttt{u32}.
    In particular, fractional literals cannot be silently rounded during extraction.
    On line \ref{line:threshold_value}, normalize the public comparison threshold:
    dense and ordinal ranks are one-based, while permuted indices are zero-based.
    A strict one-based comparison subtracts one (saturating at zero);
    an inclusive zero-based comparison adds one (rejecting overflow).
    Otherwise the threshold is already the contribution bound.
    Both matchers receive this normalized bound; they reject unsupported enumerations.

    By the postconditions of \rustdoc{transformations/make_stable_lazyframe/truncate/matching/fn}{match\_num\_groups\_predicate},
    and \rustdoc{transformations/make_stable_lazyframe/truncate/matching/fn}{match\_per\_group\_predicate},
    \texttt{num\_groups} and \texttt{per\_group} are optional bounds on the number of groups and row contributions per-group, respectively.
    If both are not defined, then the predicate is not a truncation,
    and an error is raised on line \ref{line:check_bounds}.

    Otherwise, the matched bound and its deferred checks are returned on line \ref{line:return}.
    The caller validates every candidate before use.
\end{proof}
